良率异常排查 Agent：调用流程

一句提问进来，Agent 在本地大模型和 4 个 MCP 工具之间来回 5 轮，约 28 秒给出带证据链的根因报告。下面三张图分别讲：系统由哪几块组成、一次真实运行的完整时序、Agent 循环的判断逻辑。

1. 系统架构

Agent 是中间的调度者。它不懂良率，只负责把问题交给模型、替模型执行工具、把结果交回去。工具通过 MCP 协议暴露，背后才是数据。

Agent 调度大模型（只做决策） MCP 协议层数据访问

2. 一次真实运行的时序

问题：「LOT-A1024 的良率从 92% 掉到 86%，帮我查一下原因。」每一轮都是：模型决定调什么 → Agent 通过 MCP 执行 → 结果追加进对话，再问模型。工具参数和返回值摘自实际运行输出。

与模型交互通过 MCP 执行工具 实线 = 请求，虚线 = 返回

3. Agent 循环的判断逻辑

整个 Agent 的核心只有这一个判断：模型这次的回复里有没有工具调用。有就执行再问，没有就结束。代码在 agent/main.py 的 run() 里，约 20 行。

4. 每个工具做了什么

数字全部由工具算好再返回。早期版本让模型自己数占比，它把 8/9 写成了 7/8，所以改成了这样。

工具输入关键计算这次的输出
get_lot_yield批次号、阈值筛低良率片，按失效图案分组，算占比；批次号自动补全 LOT-Edge-Ring 8/9 (89%)，Scratch 1/9
commonality_analysis批次号、坏片列表每台设备：坏片经过比例 − 好片经过比例ETCH-03/B 得分 1.0，第二名远低
get_equipment_alarms设备编号按设备过滤报警和保养记录1 条保养 + 2 条 RF 超限
search_8d_reports关键词关键词命中数排序，取前 38D-2025-031 排第一

5. 最终报告

摘自本次实际运行。

【结论】保养过程中 edge ring 安装偏心，导致晶圆边缘等离子体分布不均，RF 反射功率异常，从而引发 Edge-Ring 失效图案。

【证据链】
1. 低良率晶圆主要失效图案为 Edge-Ring（8/9，89%）—— get_lot_yield
2. Edge-Ring 晶圆均经过 ETCH-03/B（得分 1.0）—— commonality_analysis
3. ETCH-03/B 近期保养，更换了 edge ring —— get_equipment_alarms
4. 历史 8D 报告有相同案例 —— search_8d_reports

【置信度】高。多个工具的数据相互印证，且有历史案例直接支持。

【建议动作】（需工程师确认后执行）
1. 暂停 ETCH-03/B，检查并校准 edge ring 安装
2. 重新校准 RF 匹配
3. 保养 SOP 增加安装同心度检查
4. 通知工艺工程师做等离子体均匀性测试

【其他发现】
少数晶圆为 Scratch 失效，不在共性分析范围内，可能为独立问题。
